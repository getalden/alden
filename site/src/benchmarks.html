150 test PRs in four repos

Alden 0.2.2 on macOS, Apple silicon, 4 October 2026. We opened 150 PRs of varying risk in four repos and asked for our own review on each: docs typos, migrations, dependency bumps, changed public signatures, likely secrets, stacked PRs, conflicts, a prompt injection and more. Then pnpm e2e:verify ranked the queue and briefed every PR with Alden's checks and code graph, without a model, and compared each PR's lane (Needs you or Fast-track), the reasons on its queue row and the checks it flagged with what that scenario expects.

Callers outside the diff were found in all four languages (TypeScript, Python, Go and PHP), including a PHP method reached through a trait.

What it missed

  • Python callers through relative imports (production repo). A Python function's signature changed, and its callers outside the diff, which import it with from .module import …, weren't flagged. Being fixed for 0.3.
  • Importers of a renamed module. The briefing shows the file as renamed, but doesn't list the code that imports it by its old path. Being fixed for 0.3.
  • A conflicting PR (production repo) ranked without "has conflicts" among its reasons. The same scenario said so in the other three repos.
  • A dependency patch bump (Grafana) wasn't flagged by the dependency check.

Security behaviour

  • A likely secret in a PR was flagged, never shown, and never sent to the model. Detection is heuristic: see Privacy and data.
  • Text in a PR written to give the reviewer's AI instructions (a prompt injection) was not obeyed.

With a model: did the briefing point at what later broke?

The model is optional and off until you add one. Everything above was measured without it. This part uses pnpm eval on 33 recorded public PRs from Django, Grafana, Hugo, Laravel, Next.js, the GitHub CLI and Prometheus, with claude-sonnet-5 at its default effort and the diff only (no clones for the code graph). Fifteen of the 33 are PRs that a later PR had to fix; the question is whether the briefing flagged the files the fix changed: 29 files in all. Both runs were on 4 October 2026, from a development build between 0.2.2 and 0.3.

In the first run, 6 of the 33 briefings didn't finish: on five PRs the model's answer was cut off, and one call failed. Alden now asks again at low effort when the model runs out of room, and the second run repeated just those six: five finished. "Both runs" counts each PR's briefing from the second run where there is one.

"Flagged" means one of Alden's checks or a model finding pointed at the file; "In Needs your eyes" means it was one of the few places the briefing put first. By language, both runs:

In the end-to-end session the same day, 46 model briefings on large PRs cost $4.90 with claude-sonnet-5: about $0.11 each. What you pay depends on the PR's size and your model, and Alden checks every call against your caps ($0.50 a briefing and $10 a day by default) before it's sent.

What these numbers don't tell you

  • The 150 test PRs and what each should produce were written by us, to give every check something to find. They show Alden does what it's built to do, not how useful it is in your repos.
  • The model results are one or two runs over 33 PRs, 15 of them with a known regression. Models aren't deterministic, and a small set moves a lot with each PR.
  • The real measure is whether reviewers find the flags useful. That's what the beta is for: tell us in the Alden Community on Discord.

Run them yourself

pnpm e2e:seed --repo owner/name --clone <path>     # open the test PRs and request your review
pnpm e2e:verify --repo owner/name --clone <path>   # rank and brief them, no model, and compare
pnpm eval --no-llm                                  # the recorded PRs, checks only: free
pnpm eval --yes                                     # with your model; without --yes it prints the cost

How each works, and what the seed needs (a GitHub App to open the PRs), is in Evals. The scripts are in Alden's repo, which opens with the source after the beta; the three test repos linked above are public now.
